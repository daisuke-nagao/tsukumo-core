# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- Added host context matrices and real-trap QEMU regressions for waits and task termination from ISR, interrupt-disabled and prelaunch contexts, including unchanged state, error precedence and dispatch after ISR return.
- Added QEMU startup failure injection for initial/idle task creation and starting, a failure with interrupts enabled, and normal startup through the same link wrappers. The tests check failure records and prevent continuation into scheduling, timer startup or initial launch on both clocks.
- Added host regressions and a `semaphore-wait-release` QEMU suite for FIFO/priority ordering with FIRST/CNT allocation: notification before head timeout or forced release, and deletion with zero or one available unit. The host checks queues, timers and dispatch requests; QEMU checks actual wait return values on both clocks.
- Added host regressions for NULL semaphore/flag creation packets and flag wait output pointers, including free-slot preservation, error precedence, unchanged state and interrupt state. The semaphore and event-flag QEMU suites also check NULL refusals and subsequent normal use.
- Added tests of the fixes below: three on the PC of the units a departing semaphore waiter hands on (by time limit, by `tk_rel_wai()`, and none on delete) and the case `a_leaving_head_hands_its_units_on` in the `semaphore` suite; PC tests of `tk_clr_flg()`, of a second waiter on a `TA_WSGL` flag whose pattern is set, of a request above a semaphore's maximum, of `MERCD()`/`SERCD()`, of the attributes `tk_cre_mbx()` refuses and of `tk_dly_tsk(UINT_MAX)`; the case `di_fills_a_variable_named_status` in the `wait-context` suite; and the boot argument check of the `bss-clear` suite (`BOOT ARG OK`).
- Added PC tests of behavior that had none: the task switch each wake call requests (`tk_wup_tsk()`, `tk_rel_wai()`, `tk_set_flg()`, `tk_snd_mbx()`, `tk_del_mbx()`, `tk_sig_sem()`) only for a task of higher priority, `tk_sig_sem()` serving two waiters in queue order under `TA_FIRST` and `TA_CNT`, a `TA_WMUL` flag waking several waiters with a clear seen by the waiters behind, and the `TA_TPRI` queue order of flag waiters and of mailbox receivers.
- Added `debug-lto`, `relwithdebinfo-lto` and `minsizerel-lto` presets, so the tests run at -O0, -O2 and -Os with and without link-time optimization.
- Added the `memcpy` suite (`qemu-memcpy`): `tkmc_memcpy()` over lengths 0 to 70 and source and destination offsets 0 to 3, and `tkmc_memcpy()`/`tkmc_memset()` on a struct and on `UW`, `float` and `double` arrays read back through their own types. Added the `word-access-tbaa` test, which checks in clang's IR that the word loops of both functions access memory as a type that may alias any object.
- Added tests of how the timer interrupt counts time: four on the PC (0, 1, 10, 11 and 14 periods before one interrupt, also across the low-word wrap; a repeated interrupt at the same time; one late interrupt over waits of different lengths; a wait that begins while an interrupt is pending) and the case `a_held_back_interrupt_counts_every_period` in the `task-timer` suite.
- Added tests of wake-up requests and `tk_rel_wai()`/self-wakeup: two on the PC (a request queued during a semaphore wait is still there after `tk_rel_wai()` and used up by the next sleep; a task that wakes itself with interrupts on gets `E_OBJ` at count 0 and at the limit, and nothing changes) and the cases `release_wait_keeps_a_queued_wakeup` and `task_cannot_wake_itself` in the `task-timer` suite.
- Added tests of the order in which a new semaphore request takes units: three on the PC (a table of `TA_TFIFO`/`TA_TPRI` × `TA_FIRST`/`TA_CNT`, a request of higher, the same or lower priority than the head, one unit or none left, as a poll and with a time limit; a wait for ever; and requests that find no waiter) and four cases in the `semaphore` suite (`fifo_first_keeps_the_head_ahead`, `tpri_first_lets_only_a_higher_priority_pass`, `cnt_lets_a_small_request_pass`, `refused_request_is_served_after_the_head`).
- Added host boundary tests of queued wakeups for ready, running and semaphore-waiting tasks, including unchanged queues and interrupt state on refusal and re-queuing after consumption. The `task-timer` QEMU suite also queues and consumes all 4095 requests for ready and semaphore-waiting tasks.
- Added tests of the counts a semaphore takes: nine on the PC (counts out of range and their order against `E_RSATR` and `E_LIMIT`, both ends of the range, signals past the maximum or near `INT_MAX` with and without waiters and with interrupts off, each refusal checked to change nothing) and the cases `counts_out_of_range_are_refused` and `signal_past_the_maximum_keeps_the_count` in the `semaphore` suite.
- Added tests of time limits near `INT_MAX`: a table on the PC over the five wait calls that checks the tick count for 1, 9, 10, 11, `INT_MAX - 9`, `INT_MAX - 8` and `INT_MAX` ms, and the case `longest_sleep_counts_its_ticks` in the `task-timer` QEMU suite.
- Added tests of calls with an ID out of range: a table on the PC over every call that takes an ID (0, -1, `INT_MIN` and one above the maximum are `E_ID` and change nothing; 1 and the maximum get past the check), rows for `tk_wai_flg()` with interrupts off, and cases for IDs 0 and -1 in the `task-restart` and `event-flag` QEMU suites.
- Added tests of wait calls made with interrupts off: six on the PC (every call and time limit, a call that could succeed at once, the order against the argument and object checks, and `tk_dly_tsk(0)` with interrupts on) and the `wait-context` QEMU suite (`qemu-wait-context`), which also checks that a refusal uses up no wake-up request, unit, pattern or message.
- Added tests of what `tk_cre_tsk()` refuses: fourteen on the PC (each rejected input breaks one rule only, and a refusal is checked to change nothing) and the `task-create` QEMU suite (`qemu-task-create`), which also covers the 32 bit address wrap and a negative stack size at a low address.
- Added host regressions for task frame reconstruction, runtime state reset and rejected starts, plus a `task-restart` QEMU suite that restarts the same task 100 times using both explicit exit and function return.
- Added host tests for full-width timer startup, low-word wrap, read-time carry and RV32 compare write order, plus a `timer-wrap` QEMU suite on both instruction-count and host clocks.
- Added tests of deleting a semaphore that tasks wait for: five on the PC (release with `E_DLT`, the time limit of a released waiter, the free list afterwards, the task switch it asks for) and the case `delete_releases_waiters` in the `semaphore` suite.
- Added tests of waits that end by a time-out, then a signal or set before the task runs again: seven on the PC (`host-tests`, whose queue check now covers the wait queue of every semaphore, event flag and mailbox) and one case each in the `semaphore` and `event-flag` suites.
- Added the `bss-clear` test suite (`qemu-bss-clear`): `test/bss_dirty_entry.S` runs first, fills `.bss` with 0xa5 and starts the kernel as a board with dirty RAM would, and the suite checks that no 0xa5 is left.
- Added tests of `tkmc_memset()`: one matrix of every fill value, lengths 0 to 70 and offsets 0 to 3, run on the PC with UBSan (`host-tests`) and on QEMU (`qemu-memset`, with the shift check built in as a trap).
- Added a test runner (`test/runner.c`) that runs test cases one by one in their own tasks and prints a result line per case and a summary:
  - A failed assert ends only its own task, so later cases still run.
  - A case that does not finish in time is reported as a timeout and aborts the suite.
  - `selftest-*` ELFs check the runner itself and are run by `qemu-selftest-*` tests.
- Added unit tests of the kernel logic that run on the PC (`cmake --preset host`, `ctest --preset host`): a property test of `kernel/list.h` against a model, and tests of a single semaphore waiter, sleeping, time-outs (their rounding, order and the context switch they request) and the timer handler on a fake machine, built with AddressSanitizer and UBSan. The RISC-V build is selected by a toolchain file; without one the PC tests are built.
- The QEMU tests run with `-icount shift=5` by default (`QEMU_ICOUNT_SHIFT`), so guest time follows the instruction count: the UART log is the same on every run and the ctest set (without the host-clock runs, `ctest -LE host-clock`) takes about 3 seconds instead of 11. Each passing suite also runs once on the host clock (`qemu-<suite>-hostclock`, label `host-clock`) to catch races a fixed schedule hides. An empty `QEMU_ICOUNT_SHIFT` puts every test on the host clock.
- Split the kernel tests into suites, one ELF and one CTest each: `task-timer`, `event-flag`, `semaphore` and `mailbox`. Each case runs on its own, checks that its helper tasks really ran, and ends QEMU with a status that CTest judges.
- Added `CMakePresets.json` to define build and configure presets:
  - Presets include `debug`, `release`, `relwithdebinfo`, and `minsizerel` for different build configurations.
  - Common settings are inherited from the `base` preset, using the Ninja generator and exporting compile commands.
  - Supports `CMAKE_TOOLCHAIN_FILE` for RISC-V bare-metal toolchain configuration.
- Added the RV32 assembly of the kernel: `kernel/asm/rv32/start.S` (boot, the trap vector, and the handlers that save and restore a task's registers around a switch or a timer tick), `launch_task.S` (`__launch_task`, which starts the first task from its saved frame) and `idl_tsk.S` (the idle task).
- Added `putstring.h` to provide a helper function for UART-based string output.
- Added `kernel/list.h` to implement a doubly linked list utility:
  - Provides functions like `tkmc_init_list_head`, `tkmc_list_add_tail`, `tkmc_list_del`, and `tkmc_list_empty`.
  - Macros for container manipulation (`tkmc_list_entry`, `tkmc_list_first_entry`).
- Added task management in `kernel/task.c`, `kernel/timer.c` and `kernel/start.c`: `tk_cre_tsk()`, `tk_sta_tsk()`, `tk_ext_tsk()`, `tk_exd_tsk()`, `tk_slp_tsk()`, `tk_wup_tsk()`, `tk_rel_wai()` and `tk_dly_tsk()`, a preemptive priority scheduler that is FIFO within a priority (`tkmc_yield()`), and the idle task.
- Enhanced `typedef.h.in` with additional application-specific types:
  - Attributes (`ATR`), error codes (`ER`), function codes (`FN`), and priorities (`PRI`).
- `CMakeLists.txt` generates `typedef.h` from `typedef.h.in` with `DetermineTypes.cmake`, which finds the C types of each width.

### Changed
- `tk_dly_tsk()` takes a `RELTIM` (unsigned milliseconds), which `tk/typedef.h` now defines, as μT-Kernel 3.0 declares it: a delay up to `UINT_MAX` ms (about 49.7 days) is accepted, and there is no invalid delay. It took a `TMO` and refused the upper half of the range as negative with `E_PAR`.
- The PC tests run with UBSan's null check on (`tkmc_offsetof()` is `__builtin_offsetof`), and `HOST_EXPECT_WAIT` no longer counts a context switch request left by an earlier call, so a wait call that forgets to request one fails. The test runner's stack pool holds 48 tasks per suite, up from 32.
- `T_MSG`'s link is now a `tkmc_list_head`, which `tk/tkernel.h` declares; `struct dummy_struct` is gone. The layout is the same, but code that named `dummy_struct` or its members no longer compiles.
- `TK_SEMAPHORE_MAXCNT` is now 32767, the least that μT-Kernel 3.0 asks for, and `tk_cre_sem()` enforces it; it was 4095 and not checked.
- Every way a wait ends (time limit, signal, set, mailbox delivery and delete, `tk_rel_wai()`, `tk_wup_tsk()`) now goes through one function, `tkmc_complete_wait()`, which takes the task off the timer queue and the wait queue of its object and makes it ready once.
- `tsukumo-core.elf` is now the kernel only (an empty `usermain`); the tests moved into the suite ELFs.
- Refactored `kernel/asm/rv32/start.S`:
  - Improved alignment with `.balign 4`.
  - Updated handling of the global pointer (`gp`) with `.option norelax` and `.option relax`.
- Applied consistent SPDX license header formatting across all source files.
- Refactored task management in `kernel/task.c` and `kernel/start.c`:
  - Replaced custom TCB linked list management with the new `tkmc_list_head` from `list.h`.
  - Added priority (`itskpri`) to `TCB` for task scheduling.
  - Simplified context switching logic with priority-based scheduling.

### Removed
- Removed the old chained tests (`test/task1.c` to `test/task4.c` and their helpers) and the `tsukumo-core-inject-fail.elf` check; the suites and the runner self-tests replace them.
- Removed custom linked list implementation in `kernel/task.c` in favor of the new `kernel/list.h`.
- Removed `tkmc_context_switch` in favor of the more flexible `tkmc_yield` function.

### Fixed
- Track single-level ISR execution independently of MIE in the RV32 timer/dispatch entries. Wait APIs reject ISR or absent-current calls with `E_CTX` before state changes. Invalid `tk_ext_tsk`/`tk_exd_tsk` calls record a separate context failure and stop with interrupts disabled instead of changing a task and returning. ISR interrupt re-enabling and nested interrupts remain unsupported.
- Check initial and idle task creation/start results during boot. On failure, preserve the stage and original error separately from CPU trap records, disable interrupts and enter a non-returning startup panic hook. The weak default stops without cleanup or retry.
- `tk_cre_sem()` and `tk_cre_flg()` now reject NULL creation packets with `E_PAR` before reading them or allocating an object. `tk_wai_flg()` rejects a NULL output pointer with `E_PAR` after the ID range check and before context, existence, single-waiter and pattern checks, including polls. Refusals preserve kernel and interrupt state; some calls that previously returned `E_CTX`, `E_NOEXS`, `E_OBJ` or `E_TMOUT` now return `E_PAR` instead.
- Delayed timer interrupts now complete waits in deadline order. A semaphore head that times out can no longer serve a successor whose deadline occurred earlier; tests cover both deadline orders with a single interrupt delayed past both.
- On a `TA_FIRST` semaphore, a waiter that leaves without its units (its time limit runs out, or `tk_rel_wai()`) now hands them on: the waiters behind it are served from the head of the queue as far as the units go, at once. The units used to lie unused until the next `tk_sig_sem()`, while every new request was refused because a task was waiting; a producer that signals once per request stalled for good. The timer handler now ends the waits that are over one at a time, since ending one can end another.
- `tk_clr_flg()` now keeps the bits of `clrptn` (`flgptn &= clrptn`), as μT-Kernel defines it; it cleared them. Callers must pass the mask of the bits to keep, for example `~0x1` to clear bit 0.
- `tk_wai_flg()` on a `TA_WSGL` flag that a task already waits for now returns `E_OBJ` before it looks at the pattern, in the order the specification checks: a second task whose pattern is set, or one that polls, gets `E_OBJ` and the pattern stays. It used to serve the set pattern first, and could clear it (`TWF_CLR`) from under the waiting task.
- `tk_wai_sem()` now refuses a request for more units than the semaphore's maximum with `E_PAR`, after `E_NOEXS`; such a request could only wait for ever, and it did.
- `MERCD()` now gives the right main code when the sub code is not 0: it shifts, as the specification writes it, where a division by 65536 rounded toward zero (`-16` instead of `-17` for `ERCD(-17, 1)`).
- `tk_cre_mbx()` now refuses `TA_DSNAME` and `TA_NODISWAI` with `E_RSATR`, as the other objects do: the kernel has neither object names nor wait disabling. It accepted and ignored them.
- `DI()` now assigns the variable it is given, whatever its name. The macro declared a local named `status`, so `DI(status)` left the caller's variable unset, and `EI(status)` then worked from an unset value.
- `usermain()` now receives what the boot code left in `a0` (on QEMU the hart ID), as the kernel promised; `_start` overwrote `a0` while setting the trap vector, so `usermain()` got the vector address instead.
- `tk_cre_tsk()`, `tk_cre_flg()` and `tk_cre_mbx()` read each field of their packet once, as `tk_cre_sem()` did, so a packet that a task of higher priority changes during the call cannot get a value past the checks.
- `tkmc_memcpy()` and `tkmc_memset()` no longer access the caller's objects through `UW`, which C allows only for character types, so an optimizer that inlined them could have kept a float or a struct's old values. Their word loops use a type with the `may_alias` attribute (clang and GCC), and the kernel stops with `#error` on a compiler without it. The mailbox no longer reads a message's `dummy_struct` link as a `tkmc_list_head` either.
- Time limits now count the tick periods that have passed, not the timer interrupts. An interrupt held back for ten periods used to take one tick off each wait, so the waits ran about nine ticks long, and an extra interrupt before the next tick (MTIP can be cleared late after a compare write) took a tick off too early. Now a late interrupt takes off every period it missed, an interrupt that finds no period passed changes nothing, and a wait that begins while an interrupt is pending is not charged the periods from before it began.
- `tk_rel_wai()` no longer throws away the wake-up requests of the task it releases. A request queued by `tk_wup_tsk()` while the task waited for something else used to be lost when `tk_rel_wai()` ended that wait; it is now used up by the task's next `tk_slp_tsk()`. Only `tk_sta_tsk()` (and creating the task) clears the count.
- `tk_wup_tsk()` now refuses the running task with `E_OBJ`, and changes nothing, when interrupts are enabled, as μT-Kernel does for a call from a task. It used to queue a request for the caller itself. With interrupts disabled, as in a handler, the running task still gets a request queued. Code that woke its own task now gets `E_OBJ`.
- `tk_wai_sem()` no longer lets a new request take units ahead of the tasks that already wait. On a `TA_FIRST` semaphore with waiters, a request takes nothing at once, however many units are left, unless the semaphore is `TA_TPRI` and the caller has a strictly higher priority than the first waiter. A `TA_CNT` semaphore still gives a request any units it finds. Before, a small late request could pass the large request at the head of a `TA_FIRST` queue again and again. Calls that used to succeed this way now return `E_TMOUT` for a poll, or wait.
- `tk_wup_tsk()` now enforces `TK_WAKEUP_MAXCNT` (4095) when queuing wakeups and returns `E_QOVR` without changing state at the limit. It used to allow counts almost up to `UINT_MAX`. Calls that depend on more than 4095 queued requests are now refused; waking a sleeping task still succeeds without queuing another request.
- `tk_cre_sem()` now refuses a maximum outside 1 to `TK_SEMAPHORE_MAXCNT` and an initial count outside 0 to the maximum with `E_PAR`, without taking a semaphore; it used to store any counts, a negative maximum included. An unsupported attribute is still `E_RSATR` and comes first, and `E_PAR` comes before `E_LIMIT`.
- `tk_sig_sem()` now returns `E_QOVR` and changes neither the count nor the waiters for any signal that would take the count past the maximum. The check was skipped for a signal larger than the maximum, so a semaphore of one unit could hold two, and a signal near `INT_MAX` overflowed the count. The maximum is checked before units go to the waiters, as before.
- `tk_dly_tsk()` (which then took a `TMO`; see Changed), `tk_slp_tsk()`, `tk_wai_sem()`, `tk_wai_flg()` and `tk_rcv_mbx()` now accept every time limit up to `INT_MAX` ms (about 24.9 days), counted as before in 10 ms ticks rounded up plus one tick. The conversion added 9 to the signed time, which overflowed for times above `INT_MAX - 9`: undefined behavior, and on the RISC-V debug build a wait of about 4 billion ticks instead of 214748366.
- `tk_sta_tsk()`, `tk_wai_flg()` and `tk_set_flg()` now refuse an ID of 0 or below with `E_ID` and change nothing, as the other calls that take an ID already did. They checked only the upper bound, so such an ID formed an address in front of the task or flag table: `tk_sta_tsk()` read and could start whatever lay there, and `tk_set_flg()` wrote bits into it. This was also reached by passing the negative error code of a refused `tk_cre_tsk()` to `tk_sta_tsk()`.
- `tk_dly_tsk()`, `tk_slp_tsk()`, `tk_wai_sem()`, `tk_wai_flg()` and `tk_rcv_mbx()` now return `E_CTX` and change nothing when interrupts are off (in an interrupt handler, or between `DI()` and `EI()`), also for a poll, a call that could succeed at once and `tk_dly_tsk(0)`. A task is switched out when interrupts come back on, so such a call used to put the running task on a wait queue, return `E_OK` and leave the task in the waiting state until the next `EI()` switched it away. Argument errors (`E_ID`, `E_PAR`) are still reported first, except the `E_PAR` of `tk_wai_sem()` for a count above the maximum, which needs the semaphore and comes after `E_NOEXS`. The check reads the interrupt state, so a handler that enables interrupts again is not seen, and `tk_ext_tsk()` and `tk_exd_tsk()` called with interrupts off are not checked.
- `tk_cre_tsk()` now refuses a task it cannot start safely, with `E_PAR` and without taking a TCB: a NULL packet, entry or stack buffer, a priority outside 1 to `CFN_MAX_PRI`, a stack of 128 bytes (the saved frame) or less, a stack whose end wraps around the address space, and a stack whose end is not on a 16 byte boundary. It used to accept them: a bad priority indexed the ready queues out of range, a small stack put the saved frame below the buffer when the task started, and a NULL packet crashed the call. The 128 byte rule only says that the frame fits; how deep the task can go below it is up to the caller, who must also leave room for the 128 byte frame and the handler's frames that an interrupt saves on the task's stack. An unsupported attribute is still `E_RSATR`, and is checked first.
- `tk_sta_tsk()` now rebuilds the full initial register frame on every start and clears previous wakeup and wait state. A restarted task no longer reuses a frame overwritten by the previous run's stack or inherits its queued wakeups.
- The machine timer now reads and schedules all 64 bits, with stable RV32 reads and safe split compare writes. Low-word wrap no longer breaks scheduling.
- `tk_del_sem()` on a semaphore that tasks wait for now releases them with `E_DLT`, as `tk_del_mbx()` does. It used to leave them waiting for ever, and linked the semaphore's wait queue to the free list with the waiters still on it; a waiter that left later (by its time limit, for one) then corrupted the free list.
- A task whose wait times out (semaphore, event flag, mailbox) is now taken off the wait queue of the object at once. It used to stay there until it ran again, and a signal or set that came in between made it ready a second time (a self-looped ready queue), replaced its time-out cause with E_OK, and spent a semaphore unit or cleared an event flag pattern on a task that no longer waited. `tk_rel_wai()` and `tk_wup_tsk()` also leave no time limit behind on the task now.
- The kernel now clears `.bss` at boot. `clear_bss()` declared the linker symbols as `int *` variables and read the memory at them as boundaries; that is 0 on QEMU, where RAM starts zeroed, so it cleared nothing. The symbols are now declared as arrays, and the kernel calls `tkmc_memset()`. On a board whose RAM is not zeroed, `.bss` was not cleared before.
- `tkmc_memset()` no longer shifts a value of 0x80 or more into the sign bit of an `int` (undefined behaviour) when it builds the fill word; it multiplies as unsigned instead. The bytes written are the same.
- A synchronous exception (illegal instruction, access fault, `ebreak`, ...) no longer makes the CPU run the same instruction again for ever. The kernel now stops, records `mcause`, `mepc` and `mtval` in `tkmc_last_trap` and calls the weak `tkmc_panic()`, which a board or a test can replace to report the cause. `qemu-panic-*` tests check an illegal instruction, a load access fault and an illegal instruction on a bad stack.
